## 五、关键技术决策

### 5.1 为什么用 Canvas 而非 DOM？

Canvas 2D 适合高频重绘（每帧清空重画），DOM 操作在蛇身 20+ 节点时会产生大量 reflow。游戏循环中 `ctx.clearRect()` + 批量绘制比 DOM 更高效。

### 5.2 为什么单词渲染在 Canvas 内？

将单词直接画在格子上（而非用 HTML 元素叠加），避免了 z-index 管理、坐标同步、touch 事件穿透等问题。代价是文字尺寸需手动适配格子大小：

```javascript
ctx.font = `500 ${Math.max(8, CELL * 0.28)}px var(--font-sans)`
```

### 5.3 双重 API 调用的加载体验

两次 Claude API 调用（诗歌 + 意境描述）是串行的，总耗时约 3-8 秒。通过"正在创作…"点号动画缓解等待焦虑：

```javascript
let dotI = 0
const dotAnim = setInterval(() => {
  dotsEl.textContent = ['…', '.. ', '.', ' ..'][dotI++ % 4]
}, 400)
```

### 5.4 主题自适应

所有颜色使用 CSS 变量，唯独蛇身和单词方块使用硬编码十六进制，原因：

- 蛇（`#0F6E56` / `#5DCAA5`）和食物（`#D85A30`）需要在明暗两种背景上都保持高对比度
- 通过 `getTheme()` 检测当前主题，动态切换蛇身颜色

```javascript
function getTheme() {
  const v = getComputedStyle(document.documentElement)
    .getPropertyValue('--color-background-primary')
    .trim()
  return !v || v.includes('255') || v === '#fff' ? 'light' : 'dark'
}
```

## 六、单词库设计

共 80 个词，覆盖以下语义类别：

| 类别 | 示例词汇 |
| --- | --- |
| 自然意象 | ocean, moon, forest, river, tide, frost, mist |
| 光与影 | light, shadow, glow, ember, spark, flicker |
| 情感状态 | dream, silence, solitude, wonder, memory |
| 动态意象 | dance, surge, plunge, cascade, tremor |
| 具体物象 | compass, lantern, anchor, mirror, candle, prism |
| 空间感 | horizon, zenith, abyss, hollow, summit, cliff |

词库设计原则：

1. 以名词和形容词为主，意象感强
2. 多音节词优先（更有诗意）
3. 避免过于口语化的词（如 run, eat, good）
4. 中英文意象对应性好（便于 AI 创作中文诗）

### Vibe Coding 适合做什么

- 原型快速验证（本项目从 0 到可玩原型 < 10 分钟）
- 游戏 / 工具 / 数据可视化等自包含产品
- 有清晰"感觉"目标但不确定技术路径的需求

### Vibe Coding 的局限

- 复杂业务逻辑需要人工审查 AI 的状态管理
- 性能优化和边界情况需要额外迭代
- AI 生成的代码需要人工理解后才能持续维护
