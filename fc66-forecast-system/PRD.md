## 2. 系统模块 — 预测模型引擎

### 2.1 预测引擎架构设计原则

国内宠物基准收入子模型遵循 **TCSS 架构**，核心落在 **MCL（引擎）→ DCL（数据）→ 报表（输出）** 三层。该子模型有独立的输入配置、计算逻辑和输出接口，支持单独启用/停用/配置，与其他子模型共享 KPI 参数。

| 层 | 组件 | 职责（本子模型） |
| --- | --- | --- |
| MCL 计算引擎 | Rev_F3 三分项计算 + 数据规范/风控规则 | 装机产出、合规囤货折减、任务返利测算，输出基准收入 |
| DCL 数据采集 | CRM 装机/检测、SFE 进销存、经销商商务单价、返利政策 | 提供仪器 SKU 检测次数、SKU 单价、囤货与返利参数 |
| 输出层 | fact_revenue_forecast + KPI + 报表 | 按 BU/经销商/期间汇总国内宠物基准收入，KPI 预警与版本锁定 |

### 2.2 基准收入构成总览

**国内宠物基准收入 = 稳态装机产出（分项①）+ 合规经销商囤货（分项②，含压货风控）+ 经销商年度任务返利测算（分项③）**

三个分项相互独立、口径不重叠：

- 分项① 规范已装机存量仪器带来的经常性试剂/服务收入
- 分项② 规范经销商为正常经营/年度任务而进行的合理囤货
- 分项③ 规范完成年度任务后的返利驱动增量

| 分项 | 名称 | 经济含义 | 对应细化要求 |
| --- | --- | --- | --- |
| ① | 装机产出基准 Rev_install | 存量装机仪器的稳态试剂/服务收入 | 细化 1 |
| ② | 合规经销商囤货 Rev_stock | 满足合理正常囤货的收入 | 细化 2（压货风险） |
| ③ | 任务返利测算 Rev_rebate | 经销商完成年度任务后的返利驱动 | 细化 3 |

### 2.3 与相邻预测节点的边界

本节点与 **Rev_F11**（CRM 计划投放的仪器产出）不同：Rev_F11 仅计算未来新投放仪器的增量产出；本节点分项① 只计算已投放存量仪器，二者互斥。

## 3. 计算逻辑与计算公式

### 3.1 顶层公式

```
Rev_F3(国内宠物基准收入) = Rev_install + Rev_stock + Rev_rebate
```

**汇总层级**：先在「经销商 × SKU」粒度计算，再向 BU（国内宠物）与期间（FC7–12）汇总。所有金额以含税销售净额口径，币种人民币。

### 3.2 分项① 装机产出基准 Rev_install（细化 1）

**计算逻辑**：对每一台已投放仪器（按设备 SN），取其最近 X 个月每个 SKU 的月均检测次数，通过该 SN 识别到绑定经销商对应该仪器 SN 的仪器商业模式，乘以对应 SKU 的年度商务价格，得到单台单 SKU 月度产出；对所有 SN 与 SKU 求和，再乘 6 个月折算为半年基准。

```
Rev_install = Σ_SN Σ_SKU  T[SN,SKU] × P[dealer(SN),SKU] × 6
```

**变量定义**：

| 符号 | 含义 | 取数说明 | DCL 来源 |
| --- | --- | --- | --- |
| SN | 已投放仪器序列号 | 仅含状态=在用的存量仪器 | DCL-03 / dim_device |
| SKU | 该机型消耗的试剂 | 按 device_model 关联投放模式可用 SKU | dim_sku |
| SKU | 该机型消耗的租赁服务项 | 按 device_model 关联租赁模式可用租赁服务项和 SKU | dim_rent，dim_sku |
| T[SN,SKU] | 该 SN 最近 X 个月该 SKU 月均检测次数 | X 默认=3，可配置；取最近 X 月检测计数均值 | DCL-03 CRM 装机/检测报表 |
| dealer(SN) | 该 SN 绑定的经销商 | device_sn → dim_device.customer_id | dim_device |
| P[dealer,SKU] | 经销商该 SKU 的年度商务价格 | 按经销商×SKU×年度取价（含分级/协议价） | DCL-07 经销商年度商务价格表 |
| 6 | 半年月数 | FC7–12 折算系数 | — |

### 3.3 分项② 合规经销商囤货 Rev_stock（细化 2，含压货风险准入判断）

**计算逻辑**：经销商为年底正常备货经营或完成年度任务而合理囤货，但须先通过「压货风险准入」方可计入基准收入；异常或高风险囤货部分做风险标记并按比例折减。

```
Rev_stock = Σ_dealer Σ_SKU  StockMonths[dealer,SKU] × AvgMonthlySales[dealer,SKU] × Adj
```

**准入条件**（满足其一即视为合规，Adj=1）：

1. 囤货月数 X ≤ 2 个月（X 默认=2）
2. 囤货月数与历史同期偏差在合理范围内：|X − X_历史同期| ≤ 1 个月

不满足任一条件 → 在 DCL-05 数据治理规则中标注为「渠道压货风险」，并在当期 Rev_F3 中按下表比例折减（Adj<1）或排除（Adj=0）：

| 情形 | 囤货月数 X / 偏差 | 处置 | 折减系数 Adj |
| --- | --- | --- | --- |
| 合理压货 | X ≤ 2 或 \|X−X_hist\| ≤ 1 | 全额计入 | 1.00 |
| 轻度压货 | 2 < X ≤ 3 且 偏差 > 1 | 按比例折减 | 0.70（可配置） |
| 重度压货 | X > 3 | 按比例折减 | 0.50（可配置） |

> 注：折减系数为默认配置值，纳入 KPI 参数库，可按业务复核调整；被折减的金额在审计日志中留痕。

### 3.4 分项③ 任务返利测算 Rev_rebate（细化 3）

**逻辑**：经销商完成年度任务后，按返利政策测算的返利金额并计入当年度影响，作为基准收入的组成项加总。

```
Rev_rebate = Σ_dealer RebateEstimate[dealer]
```

**变量定义**：

| 符号 | 含义 | 取数说明 | DCL 来源 |
| --- | --- | --- | --- |
| RebateEstimate[dealer] | 经销商完成年度任务后的返利测算 | 按返利政策 × 达成率 × 年度任务基数测算 | DCL-01 返利政策表、经销商年度返利测算表 |

> **口径提示**：返利在财务上作为销售折让抵减收入核算，以负号计入（收入抵减），落库时在 `fact_revenue_forecast.calc_basis` 记录该口径。

## 4. DCL 数据治理与风控规则

### 4.1 渠道压货风险判定（治理规则）

- **触发**：分项② 中任一「经销商×SKU」囤货月数不满足 3.3 准入条件
- **标注**：在数据治理规则表写入 `risk_flag='渠道压货风险'`，记录 dealer/SKU/X_2026/X_历史同期/Adj
- **处置**：当期 Rev_stock 按 Adj 折减；风险明细进入审计日志（ctl_audit_log）与风险清单报表

### 4.2 SN-经销商识别与仪器商业模式的价格取数

- **识别链**：检测记录(device_sn) → dim_device.customer_id → dim_customer → dim_rent，dim_sku → 取该经销商年度商务和租赁价格
- **缺价兜底**：若某经销商×SKU 无年度商务价格，回退至 SKU 标准 ASP（dim_sku 关联价），并标记 `price_fallback=TRUE` 显示提示和复核

### 4.3 数据质量校验

- SN 唯一性、状态=在用方可计入分项①；退机/停用 SN 当期剔除
- 检测次数窗口 X 一致性：所有 SN 采用同一 X（默认 3 月），不足 X 月按实际月数取均并标记
- 囤货历史同期 X_历史同期：需可回溯至上一年度同期版本

## 6. 对 DCL 数据源建模 URS

### 6.1 URS 建模总原则

- **维度要求**：所有数据至少关联到 公司 / 业务单元(BU) / 预测版本(version) / 期间(period) 四个维度
- **版本控制**：每条数据携带 version_id（FC6+6 版本），支持多版本并存与回溯；审批后整版锁定不可改
- **至少细化到两个粒度**：SKU 粒度（试剂/耗材）+ 设备 SN 粒度（仪器/装机产出），二者通过 device_model / linked_sku 关联
- **KPI 设置与预警**：内置 KPI 数据库，自动匹配、阈值预警、数据锁定
- **H/AI/H 治理**：H/AI/H 三级管控权限工作流，每张 DCL 表可被审批记录(ctl_approval)与审计日志(ctl_audit_log)追踪，批准即锁并留痕
- **报告自动生成**：连接标准模板，管理科目自动分拆和合并，FC6+6 文件下载和可视化
